## 地图瓦片加载提速（2.63.1，用户先问原因、同意后实施）

用户问「地图加载太慢是什么原因，可以优化吗」→ 按 2026-09-11 新规则**先诊断不改码**，列原因与方案表，用户回「开动」才实施。

诊断结论（按影响排序）：
1. `putCachedTile` 每张瓦片写完都触发 `evictIfNeeded` → `getTileCacheStats` 全表 `each()` 统计（上限 2 万条含 Blob），超限再 `toArray()` 整表载内存——浏览新区域几十张瓦片 = 几十次全表扫描（最大坑）
2. `loadTile` 串行链路：await 清单检查（首张还要先下 28KB manifest）→ await 缓存读 → 才 fetch，网络请求比原生 img 晚一大截
3. 缓存命中每次都 `update(lastAccess)`（命中 = 2 个 IDB 事务）
4. 无 preconnect 预热高德子域；keepBuffer 默认 2

实施（版本 2.63.1，[IM]）：
- `tileCache.ts`：新增 `TILE_CACHE_EVICT_INTERVAL`=16（put 节流触发淘汰）+ `TILE_CACHE_ACCESS_REFRESH_MS`=60s（lastAccess 刷新节流）；`evictIfNeeded` 改**单次** orderBy('lastAccess') 流式遍历（统计+定位一趟完成，不再 toArray 整表载内存）
- `CachingTileLayer.tsx`：`loadTile` 本地清单检查与缓存读 `Promise.all` 并行（新增 `readCachedTile` 私有方法吞错）
- `index.html`：preconnect webrd01-04（**crossorigin 必带**，fetch cors 才能复用连接）+ dns-prefetch webst01-04
- `FallbackTileLayer.tsx`：`TILE_KEEP_BUFFER`=4 传两层
- 测试：「命中刷新 lastAccess」拆成两条（超间隔会刷新 / 60s 内不重写），`TILE_CACHE_ACCESS_REFRESH_MS` 导出供测试用
- PROGRESS.md §5 新增「瓦片缓存性能约定（勿回退）」条目

验证：全量 148 文件 1397 用例全绿 + lint/build 绿。工作区另有并行会话的 share-studio 原型等未跟踪文件，没碰。

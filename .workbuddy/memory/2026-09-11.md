## 地图瓦片加载提速（2.63.1，用户先问原因、同意后实施）

用户问「地图加载太慢是什么原因，可以优化吗」→ 按 2026-09-11 新规则**先诊断不改码**，列原因与方案表，用户回「开动」才实施。

诊断结论（按影响排序）：
1. `putCachedTile` 每张瓦片写完都触发 `evictIfNeeded` → `getTileCacheStats` 全表 `each()` 统计（上限 2 万条含 Blob），超限再 `toArray()` 整表载内存——浏览新区域几十张瓦片 = 几十次全表扫描（最大坑）
2. `loadTile` 串行链路：await 清单检查（首张还要先下 28KB manifest）→ await 缓存读 → 才 fetch，网络请求比原生 img 晚一大截
3. 缓存命中每次都 `update(lastAccess)`（命中 = 2 个 IDB 事务）
4. 无 preconnect 预热高德子域；keepBuffer 默认 2

实施（版本 2.63.1，[IM]）：
- `tileCache.ts`：新增 `TILE_CACHE_EVICT_INTERVAL`=16（put 节流触发淘汰）+ `TILE_CACHE_ACCESS_REFRESH_MS`=60s（lastAccess 刷新节流）；`evictIfNeeded` 改**单次** orderBy('lastAccess') 流式遍历（统计+定位一趟完成，不再 toArray 整表载内存）
- `CachingTileLayer.tsx`：`loadTile` 本地清单检查与缓存读 `Promise.all` 并行（新增 `readCachedTile` 私有方法吞错）
- `index.html`：preconnect webrd01-04（**crossorigin 必带**，fetch cors 才能复用连接）+ dns-prefetch webst01-04
- `FallbackTileLayer.tsx`：`TILE_KEEP_BUFFER`=4 传两层
- 测试：「命中刷新 lastAccess」拆成两条（超间隔会刷新 / 60s 内不重写），`TILE_CACHE_ACCESS_REFRESH_MS` 导出供测试用
- PROGRESS.md §5 新增「瓦片缓存性能约定（勿回退）」条目

验证：全量 148 文件 1397 用例全绿 + lint/build 绿。工作区另有并行会话的 share-studio 原型等未跟踪文件，没碰。

## Bash 工具链修复（2026-09-11 下午，已改用户 PATH）

根因定位（链式）：coreutils **文件完好**（PortableGit usr\bin 356 个文件都在），但 Windows PATH（系统+用户）从未包含任何 Git 的 usr\bin；宿主 bash 是非登录/非交互模式，BASH_ENV 指向的 shim 脚本第 3 行就调 dirname → 自身目录解析失败 → safe-delete 不初始化 → `ls/head/tail/rm` 全灭、codegraph 钩子路径错乱（`F:\node_modules\...`）、safe-delete 报 trash-failed——全部同一源头。

修复（用户确认后执行）：向**用户级** PATH（HKCU\Environment，REG_SZ）追加 `C:\Users\SERVER\.workbuddy\binaries\PortableGit\versions\1.2.0\usr\bin`（registry API 追加，不用 setx 防截断；追加到用户级尾部不会遮蔽 system32 的 find/sort）。改前原值备份在 `<repo>/.tmp/path-backup.txt`，`setx WORKBUDDY_ENV_REFRESH 1` 哑变量触发广播。冒烟：新 PATH 下 bash 的 dirname/ls/head/tail/wc 全链路零报错。

**生效条件**：需重启 WorkBuddy（环境变量只对新进程生效；若重启后仍旧，注销重登一次）。修好后应验证：agent bash 的 `ls` 可用、删除文件不再报 trash-failed、`codegraph sync` 恢复。回滚 = 从用户 PATH 移除该条目。

## 2.68.1 修复 TabBar 桌面端误显示（用户截图反馈，ed57af6 已发布）

- 基础样式必须显式 `display:none`，只靠媒体查询内「正向显示」不够——桌面没有规则就按默认布局渲染
- **vitest 会处理 CSS**（本项目配置），jsdom 里 `display:none` 元素对默认 `getByRole` 不可见：查询要加 `hidden:true`（旧汉堡测试注释早就写过这个坑，别再踩）
- dom-accessibility-api 对隐藏元素**accessible name 计算为空串**——即使有 aria-label，`getByRole('navigation', { name })` 也查不到；用 class 定位 + `toHaveAttribute('aria-label')` 断言绕开

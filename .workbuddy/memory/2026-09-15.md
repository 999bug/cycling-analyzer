## 赛段页进入提速（seg-perf，已提交 857bb89，版本 2.89.0）

### 根因
- 赛段页成绩榜缓存是**模块级内存变量**，`SegmentsPage.tsx` 每次挂载都要
  `getRecordsByActivityIds(全部活动)` 拉几十万点 → Worker 计算 → N 个事务写库，
  刷新页面缓存即失效，所以「每次进赛段都要等」。
- 落库的 `segment_efforts`（v6 就有的产物）**从没被优先读过**，只当写入终点。

### 做法（两段式 stale-while-revalidate）
1. 进入即 `listEffortsBySegments()` 读落库直出渲染；从未扫过且库里无成绩才留
   「成绩计算中…」（否则会先闪一帧空榜）。
2. 后台 `refreshBoards()` 用持久化的扫描状态 diff：新增赛段才全量扫，
   仅活动新增/纠偏时只扫变化的那些；扫完 `mergeEffortsForActivities()` 合并落库，
   **再从库里读回**合并结果（增量结果只含被扫活动，直接渲染会丢旧成绩）。
- 状态存 `scan_cache`（`src/storage/segmentScanState.ts`，fingerprint = 结构版本）。
- 删除活动必须 `pruneSegmentScanState()`（已接进 `deleteActivities/deleteAll`），
  否则同一活动重新导入时 id 与坐标态都没变 → 判成无需扫描 → 成绩永远补不回来。

### 验证
全量 1643/1643 + lint/tsc 绿；新增 `tests/storage/segmentScanState.test.ts`、
赛段页「二次进入不拉逐点」「新增活动只扫该活动」两例（后者曾暴露增量结果覆盖完整榜单的 bug）。

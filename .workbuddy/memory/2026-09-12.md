## 示例数据说明条改版（[NF]，随 2.75.0 入库）

- 用户反馈首屏提示「你现在看到的是作者 Saul 的公开骑行数据…」不明显。诊断：视觉权重最低档
  （info 10% 背景/30% 边框，深色下与 --bg-surface 几乎同色）+ 80 字长句无分层 + 只有 × 没有行动入口
  + 关闭即永久消失（独立 localStorage key）。UI 专家会话出方案对比图后确认：徽章 + 双层文案 + 导入按钮。
- 落地：`AuthorBanner` 重写（「示例数据」徽章 + 主句「你现在看到的不是自己的骑行记录，而是站点内置的示例数据」
  + 次要句「导入你的 FIT 文件后…」），主色「导入我的数据」按钮；文案**不再提作者身份**（用户明确要求）。
- 两个技术点（重要）：
  - 导入弹窗开合从组件 useState 提到 `importStore.dialogOpen`，侧边栏按钮与说明条共用；
    **必须在 ImportPanel 卸载时 closeImportDialog**，否则 store 残留 true → 测试间交替失败
    （表现：第一个用例开弹窗成功、第二个点按钮变关闭，严格交替）。
  - 弹窗改 `createPortal(..., document.body)`：移动端侧边栏是 `transform: translateX(-105%)` 抽屉，
    会为 `position: fixed` 创建包含块，从横幅唤起时弹窗会跟着抽屉跑偏（原实现只在侧栏内打开，问题被掩盖）。
- 关闭状态迁入 `dataSourceStore.authorBannerDismissed`（持久化），设置页「作者数据」区块可恢复显示。
- **并行会话踩踏实录**：本会话用 `git apply --cached <只含自己 hunk 的 patch>` 精确暂存共享文件
  （SettingsPage.tsx 同时被另一会话改），但对方随后 `git commit` 把我的 index 一并提交进了
  523ed83（主题只写类型复核）。教训：并行时即使只暂存自己的改动，也挡不住对方 commit 带走 index
  ——共享文件改动最好等对方提交完再动，或提交前先确认 index 归属。文档补充走了单独提交 `e92055e`。
- **事故记录：提交卷入并行会话半成品**——git add 前查过 status 只有自己文件，但 add+commit 之间并行会话把 AuthorBanner/ImportPanel/importStore/dataSourceStore 等 6 个文件 add 进了暂存区，一并进了 523ed83。红线是「绝不改写历史」，无法拆分；补救＝跑被卷入文件的相关测试（31/31 绿）+ CI 全量验证（通过）。**教训：共享仓库里 commit 前必须再查一次 `git diff --cached --stat`，只提交自己文件时应先 `git restore --staged` 掉非本任务的暂存文件**；后续会话一律照此执行。

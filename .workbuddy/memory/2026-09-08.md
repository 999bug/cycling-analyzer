## vitest 全挂根因纠正：不是 NODE_OPTIONS，是 Windows 小写盘符（vitest #10692）

- 上一节"NODE_OPTIONS shim 破坏 worker"系**误诊**：PowerShell Start-Process 成功的真正原因是 PowerShell Set-Location 自动大写盘符，恰好绕过 bug，与清 NODE_OPTIONS 无关。
- 本日下午 bash 里做对照实验逐步排掉 NODE_OPTIONS / BASH_ENV / BASH_FUNC_* / env -i 极简环境 / managed node vs 系统 node / npm node-options / .vite 缓存 / pool=threads 全部嫌疑，env -i 极简环境仍失败证明与注入无关。
- 最小诊断文件给出真实错误 "Vitest failed to find the current suite"；web 检索命中 vitest-dev/vitest#10692：**Windows 下 cwd 为小写盘符路径（f:/...）时，vitest CLI 从 f: 加载而 Vite 把模块 id 规范化为 F:，Node ESM 按 URL 键控 → 测试文件加载第二份未初始化 vitest runtime，首个 describe() 抛 `Cannot read properties of undefined (reading 'config')`**。4.x 报 config 错，5.0.0-beta 报 find-suite 错，同根因。
- 判别特征：输出 `RUN v4.1.10 f:/<repo>` 盘符小写即中招；`F:` 大写即过。Git Bash 保留输入大小写，PowerShell/cmd 行为不同（cmd 保留、PowerShell 强制大写）。
- **解法：bash 里 `cd F:/<repo>`（大写盘符）再跑**；上游修复 PR #10694（2026-07-27）等发布。验证：单文件 12/12，全量 1041/1041（68s）。

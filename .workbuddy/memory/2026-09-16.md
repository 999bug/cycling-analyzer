## 建段弹窗：全屏按钮失效 + 命中次数偏少（2.89.2）

- **全屏按钮无效**：`SegmentCreatorDialog.tsx` 声明了 `mapWrapperRef` 却没挂到 `.segment-creator__map` 上，
  `MapFullscreenButton` 内 `targetRef.current` 恒为 null → `toggleFullscreen` 首行 return，原生全屏与伪全屏都走不到。
  修：包裹层加 `ref` + `map-fullscreen-wrapper` 类。其余 4 个调用点（ActivityMap / Heatmap / RoutesMap / CompareSection）ref 都正常。
- **命中次数偏少**：`matchSegmentEffortDetail` 只认「起点圆 → 终点圆」单向穿越，建段预览只用 `draft`（时间序正向）匹配一次，
  反向骑行（往返/折返）全部漏计，且 UI 的「正向 x / 反向 y」里反向恒为 0。
  修：`segmentCreator.ts` 新增 `reverseSegmentDraft()`（起终点互换 + trackPoints 倒序），预览对每条活动用
  「展示方向几何 + 反向几何」各匹配一次；同向穿越默认记正向、反向穿越默认记反向，净位移能判定时以 `effortMatchesDirection` 为准。
- 口径说明：赛段成绩榜仍是 Strava 式单向；建段预览是「这段路被经过几次」的辅助信息，故双向统计。

## 新增错误日志功能（2.90.0）

- 需求：用户报障时错误只在控制台一闪而过，无从查证 → 「操作中报的错」落本地 IndexedDB。
- 存储：`src/storage/db.ts` DB_VERSION 6→7，新增 `error_logs` 表（`++id, createdAt, source, level`）。
  改版本号会触发老用户端升级流程（多标签 blocked/versionchange），只加表不动旧表。
- 逻辑：`src/features/logging/errorLog.ts`——`logError(level, source, error, context, db?)`、
  `listErrorLogs`、`clearErrorLogs`、`exportErrorLogs`、`installErrorLogging()`。
  三条自保约束：写库失败静默（不得再 console.error，否则与全局采集递归）、
  同一 source+message 连续重复 2 秒去重（瓦片失败刷屏）、上限 500 条淘汰最旧。
  所有函数带可选 `db` 参数便于测试注入（与设置页 context.db 注入口径一致）。
- 采集：`main.tsx` 装 `installErrorLogging()`（console.error / window error / unhandledrejection）；
  ErrorBoundary 额外记一条 source='boundary'（带 componentStack）。
- UI：`ErrorLogPanel` 挂设置页「错误日志」区块（TOC 项 id `settings-error-log`，在数据管理与安装应用之间），
  可展开堆栈/上下文、导出 JSON、清空。
- 口径：日志不属于用户数据——导出备份不含它，`clearAllData()` 也不清它（清空后仍需查错），已在 dataClear 注释写明。
- 坑：`console.error` 包装若用 `.bind(console)` 保存，卸载后还原的是 bound 版本与原引用不等（测试断言失败）；
  改存原引用 + `original.apply(console, args)`。另外 effect 内不能直接 setState（lint
  `react-hooks/set-state-in-effect`），首次加载用异步 IIFE（与 SegmentCreatorDialog 同款写法）。

## 架构审计：等效后端三层（只读诊断，未改代码）

- 背景：用户提「后端重构」。本项目**无服务器后端**，等效后端＝运行时数据平面（Dexie/IndexedDB）
  + 构建时数据平面（`scripts/buildAuthorData.ts` → `public/author-data`）+ 交付平面（Actions → Pages）。
  方案方向：不加服务器，而是立起「数据访问层」。
- 核心缺陷（带行号，后续动手直接按此定位）：
  1. `src/storage/repositories/activityRepository.ts:632` `listActivities` 全表 `toArray()` 后内存 filter+sort+slice；
     `src/storage/db.ts:456` 只有 `id, &fingerprint, startTime, activityType`，缺 `[activityType+startTime]` 复合索引。
  2. 同文件 `:580-628` `getRecordsByActivityIds` 一次 `bulkGet` 全部活动整条 blob（热力图/路线图/赛段路径）无分片。
  3. 同文件 `:561-566` `getRecords` 整行读出再 slice，分页不减 IO；逐点 1.5MB/活动。
  4. `src/features/import/importer.ts:249,251` 每文件 2 次独立事务且摘要/台账非原子；已实现的批量 `addActivities`（`:523`）零调用点。
  5. `src/storage/recordsMigration.ts:114-126` 抢锁非 CAS；`:167-168` `clear()` 与 `writeState('done')` 非原子 → 可致真实数据丢失。
  6. `scripts/buildAuthorData.ts:114-169` 零增量、明文产物（`public/author-data/records` 125MB/81 条）、无 gzip 无分片；
     `:126-131` fail-fast 单点阻塞发布；`:320` 依赖的 `author-data/segments.json` 不存在且被 `SegmentsPage.tsx:207` 静默吞掉。
     `.gitignore` 放行 `tiles/`（18MB 二进制进 git）。
  7. `src/features/ai/aiClient.ts:404-586` 流式无首字节/静默超时（`:362` 注释自认），全库无 retry/backoff，`:61` `timeoutMs` 是死参数。
  8. `src/map/CachingTileLayer.tsx:163` 未调 `navigator.storage.estimate()`、QuotaExceeded 被吞；
     `src/map/tileSources.ts:30` + `FallbackTileLayer.tsx:62-76` 降级计数无时间窗口且本会话不可回退。
- 其它：ErrorBoundary 只有整站一个（`src/app/App.tsx:41`）；`html-shell` 运行时缓存无 ExpirationPlugin（`src/sw.ts:57,70`）；
  `insightCache.ts` key 不含 model，换模型命中旧文案；`db.ts:477` 注释称 v7 物理删 `activity_records` 与实际（只加 `error_logs`）不符。
- CI：`.github/workflows/deploy.yml` 无 e2e、无体积门禁、无依赖扫描、无回滚；`errorLog.ts` 日志仅本机，线上故障不可观测。
- 交付：方案文档已写 `docs/数据层重构方案.md`（P0 止血 5 项 / P1 数据访问层 / P2 构建增量与 CI 门禁，含验收标准与风险登记册）；
  `docs/PROGRESS.md` §0 已登记「📌 待评审」。等用户评审后才动手。
- 方案里的几个关键判断（后续别推翻重来）：
  - 列表查询不能追求「零内存过滤」——12 个数值区间任意组合，索引只做预筛，精筛仍在内存；
    `queryActivityList`（`activityRepository.ts:360`）保留为纯函数 oracle 做新旧结果一致性测试。
  - 年/月筛选用的是**本地日期**前缀（`localDateKeyFromIso`），`startTime` 是 Unix 秒索引，时区边界不可互换
    → 必须新开 `localDate` 字段 + 索引，且需后台回填 + `localDateIndexReady` 就绪标志（未就绪回退全量）。
  - v8 拟加 `activity_chunks`（主键 `[activityId+seq]`，~5000 点/片）；对外契约仍 `ActivityRecord[]`，重组逻辑收敛在 repository；
    `activity_blobs` 全程保留作回退源。列式 Float32Array 是可选增强，放 P2 单独评估（会动 1600+ 用例）。
  - 分片迁移**必须先修完 recordsMigration 的 CAS 锁 + 同事务清理**再接入，否则放大丢数据风险。
  - 明确不做：上服务器、ORM、虚拟滚动、列式存储（P1）、账号同步。

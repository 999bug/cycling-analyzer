## 一、界面设计规范（移动优先）

### 1.1 现状盘点

- 全局 CSS 变量体系已存在（`src/index.css`）：深色默认 + 浅色主题覆盖变量，质量高，**保留不推翻**。
- 断点只有 `768px` 一档（侧边栏 → 抽屉）。
- 字体只有 `h1=24px` 一条规则，**缺一套完整字号刻度**。
- 无 focus ring / hover 层级 / 图表序列色板等显性 token。

### 1.2 断点体系（移动优先，5 档渐进）

| 断点 | 布局 | 说明 |
| --- | --- | --- |
| 320px（基线） | 单列堆叠，内容 padding 16px | 一切设计先在 320px 验证 |
| ≥576px | 单列 → 可选双列 | `repeat(auto-fit, minmax(280px, 1fr))` 免媒体查询网格 |
| ≥768px | 双列网格；导航保持抽屉 | 沿用现有断点，不破坏现行为 |
| ≥992px | 侧边栏 220px 常驻（现有桌面布局） | 仅细化内容区网格 |
| ≥1200px | 内容区最大宽度约束 + 三列卡片 | 图表页保持通栏自适应 |

### 1.3 配色方案（沿用 + 补齐）

深色主题（默认）：

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--bg` | `#121417` | 页面背景 |
| `--bg-surface` | `#1b1e23` | 卡片表面 |
| `--bg-elevated` | `#232830` | 浮层/弹窗 |
| `--text` / `--text-secondary` / `--text-tertiary` | `#e8eaed` / `#9aa0a6` / `#6b7178` | 文字三级 |
| `--primary` | `#b8e62e` | 品牌荧光绿（深底上对比度 > 7:1） |
| `--on-primary` | `#0d3b4c` | 主色上的文字 |

浅色主题：主色换 `#0d3b4c` 深蓝（荧光绿在白底对比度不足，现有方案已正确处理）；背景 `#f5f6f8` / 表面 `#ffffff` / 主文字 `#1a1d21`。

语义色：success `#34c759`、warning `#ff9f0a`、danger `#ff453a`、info `#4f8cff`（浅色主题各自覆盖为加深版）。

**新增 token 建议**（本次规划补齐项）：

1. `--focus-ring: 2px solid var(--primary)`——统一键盘焦点可见性，替换散落的 `outline` 写法。
2. hover/active 层级变量：`--bg-hover`（现状是各文件硬编码 `rgba(255,255,255,0.06)`）。
3. 图表序列色板：8 色以内、深浅两主题各一套，供 Recharts/地图着色统一取用。
4. 交互状态不得仅靠颜色区分（WCAG）：状态同时带图标/文字。

### 1.4 字体方案

- 字体栈**沿用现有系统栈**（system-ui + PingFang SC / Microsoft YaHei），不引入 webfont——GitHub Pages 首屏零额外加载，中文渲染最稳。
- 字号刻度（8px 基线）：

| 字号 | 行高 | 权重 | 用途 |
| --- | --- | --- | --- |
| 32px | 1.2 | 500 | 页面大标题（年度回顾封面级） |
| 24px | 1.3 | 500 | 区块标题（现有 h1） |
| 20px | 1.3 | 500 | 卡片标题 |
| 16px | 1.5 | 500 | 正文强调、关键数值 |
| 14px | 1.6 | 400 | 正文默认 |
| 12px | 1.6 | 400 | 辅助说明、图表轴标签 |

- 权重只用 400 / 500 / 600 三档；数值展示优先等宽数字（`font-variant-numeric: tabular-nums`）。

### 1.5 无障碍基线（WCAG 2.2 AA）

- 正文对比度 ≥ 4.5:1，大字号与 UI 组件 ≥ 3:1。
- 全站键盘可达、焦点可见（focus ring token）、抽屉开合已有 `aria-expanded`，保持。
- `prefers-reduced-motion` 已在布局中处理，推广到所有新增动效（仅动画 transform/opacity，0.2–0.3s）。

### 1.6 落地方式

新建 `src/styles/tokens.css`（或直接扩展 `index.css` 的 `:root`）逐项补 token，按页面渐进迁移；不动任何功能逻辑。

## 二、「周末去哪骑车」功能规划

### 2.1 定位

**骑行决策助手**，不是导航、不是社交。回答三个问题：这个周末该不该骑？什么时候骑（周六/周日 × 早/午/晚）？骑哪条（复用现有路线库）？

### 2.2 数据源调研结论

| 方案 | 鉴权 | 免费额度 | CORS | 结论 |
| --- | --- | --- | --- | --- |
| **Open-Meteo** | 无 key | 非商用免费（600 次/分限速） | 支持，浏览器直连 | ✅ **首选** |
| OpenWeatherMap | 需 key | 1000 次/天 | 支持 | 备选，key 会暴露在前端 |
| 和风天气 | 需 key | 免费额度有限 | 需确认 | 备选，国内数据可能更准 |

Open-Meteo 关键能力：逐时预报 16 天（覆盖周末）、自带 Geocoding 城市搜索、Air Quality API（AQI）、每小时更新、CC BY 4.0 数据许可（页面标注来源即可）。**与「纯前端 + GitHub Pages 无后端」架构完全兼容**。国内城市建议实测预报精度后再定是否需要备选源。

### 2.3 架构（纯前端闭环）

```
设置骑行地点（城市搜索 / 浏览器定位，仅存本地 IndexedDB）
  → Open-Meteo 周末逐时预报（localStorage 缓存，1h TTL，失败回退缓存并标注更新时间）
  → 合并本地数据：路线库 + 历史常骑时段/距离 + 训练负荷（休息日建议）
  → 条件评分引擎（纯前端函数，可单测）
  → 建议卡片：最佳时段 0–100 分 + 天气要点 + 路线深链路线图页
```

评分维度（初版权重待实测调参）：降水概率（最高权重）、气温与体感、风速、AQI、时段与用户历史偏好（常骑时段加分）。路线匹配：距离接近近期均值 + 天气加成，输出 2 条 + 周日备选时段。

### 2.4 UI 形态

- 入口：仪表盘顶部一张「本周末骑行建议」卡片（移动端单列通栏，桌面端与统计卡并排）；不新增导航页。
- 评分分级：≥80 主色高亮、60–79 中性、<60 灰显 + 文字原因（降水/大风/高温），不只靠颜色传达。
- 空态：未设置城市 → 引导设置；失败态：回退缓存 + 更新时间标注；缺失值显示 `—`（全站约定）。
- 设置项：城市（Geocoding 搜索）、可选定位授权；全部仅存本地，不上传——与访客隐私模型一致。

### 2.5 分期

| 阶段 | 内容 |
| --- | --- |
| P1 MVP | 手动选城市 + 周六/周日三时段评分卡 + 天气要点 + 失败/空态；评分引擎单元测试 |
| P2 | 接路线库推荐 + 深链路线图页；按历史常骑时段个性化 |
| P3 | 浏览器定位、AQI、训练负荷联动（如「本周负荷高，建议短距离恢复骑」） |

### 2.6 风险与不做的事

- Open-Meteo 免费档限**非商用**——本站为个人非商用项目，符合；页面标注数据来源。
- 国内城市预报精度待实测（P1 验收项），必要时引入和风天气作可选源。
- 不做：实时雷达图、导航、社交分享路线、任何需要后端/密钥的能力。

## 1. 项目速览

**骑了么（Cycling Analyzer）**：个人骑行数据分析网站（Strava Lite）。

- 纯前端，无后端：FIT/GPX 文件在浏览器内解析，数据存 IndexedDB，**永不上传**
- 部署 GitHub Pages（子路径 `/cycling-analyzer/`），SPA 路由靠 `public/404.html` 还原深链
- 技术栈：React 19 · TypeScript · Vite · React Router · Zustand · Dexie · Leaflet · Recharts · @garmin/fitsdk · Vitest · Playwright · GitHub Actions
- 双数据源：作者公开数据快照（只读）+ 访客本地数据（可写）
- 另有小程序原生重构子项目（`miniprogram/`，独立推进）

## 3. 架构硬边界（违反即返工）

### 3.1 数据分层管线

```
FIT Decoder → Normalizer → Calculator → Storage Repository → UI
```

- `src/fit/decoder`：封装 @garmin/fitsdk
- `src/fit/normalizer`：SDK 结构 → 领域模型（半周→十进制度、Date→Unix 秒）
- `src/fit/calculator`：统计计算（爬升=相邻正增量、平均速度=距离/时长）
- `src/storage`：Dexie 库 `cycling-data`
- `src/features/*`：业务功能域；`src/pages`、`src/charts`、`src/map`：展示层

**约束**：

1. React 组件**禁止**直接调用 `@garmin/fitsdk`
2. UI 只依赖 `src/types/activity.ts` 领域模型与 repository 接口
3. 新增功能先定位到对应层，**跨层直接调用视为违规**

### 3.2 领域模型是唯一跨层契约

- 单位固定：米 / m/s / bpm / rpm / W、Unix 秒、十进制度
- **缺失字段 = undefined ≠ 0**（规格 §25）：UI 一律显示 `—`，严禁伪造 0 值
  （反面案例：统计页「最高功率 0 W」，作者源无功率计时应显示 `—`，已作为 bug 修复）
- 摘要与逐点分表：`activities` 表只存摘要，逐点数据在 `activity_records`，`getRecords` 按需加载

### 3.3 双数据源规则

- 组件**不直接 new 仓库**，统一经 `useActivityRepository()` 按 `dataSourceStore` 当前源取仓库
- 作者快照源**只读**：导入/删除/改名/设赛段等写操作永远只进本地 Dexie
- UX 决策演进：作者源下写操作按钮从「隐藏」改为「置灰 disabled + title 提示」（隐藏会让用户困惑按钮去哪了，置灰+提示更友好）
- 快照拉取路径必须拼 `import.meta.env.BASE_URL`（适配 GitHub Pages 子路径部署）
- 训练配置经 `getEffectiveProfile(source)` 随源切换

## 4. 代码规范

| 项 | 规范 |
|---|---|
| 注释 | **中文** |
| 日志/异常消息 | **英文** |
| 导入路径 | 统一 `@/` 别名 |
| React 组件 | `function` 声明（非箭头函数） |
| 魔法值 | 禁止，提取常量 |
| 计算逻辑 | **纯函数优先**：输入领域模型、输出结构化结果，放 `features/*/xxx.ts` 并配 Vitest 单测 |
| 指标复算 | UI 组件不重复计算 NP/TSS/区间等指标，复用 `features/analysis/*`，**避免多实现漂移** |

**纯函数模式的实战价值**（多次验证）：

- 洞察文案生成（rideInsights）、骑行类型推断（rideSummary）、赛段匹配（segmentMatching）
  全部做成纯函数 → 可独立单测 → UI 只是薄壳
- 数据驱动的文案**严禁写死示例**：洞察必须由真实数据条件生成，不足时用概览兜底

## 5. 测试规范

- 框架：Vitest + jsdom；全量 900 左右用例约 40s
- DB 测试：`fake-indexeddb`（tests/setup.ts 已全局注册）+ **真 Dexie 实例注入**
- FIT 样例在 `tests/fixtures/`（Garmin 官方公开样例 + 合成带 GPS 文件，
  `node tests/fixtures/generate-samples.mjs` 可重新生成，不含个人真实数据）
- 页面测试用 MemoryRouter 包裹；页面数据加载支持注入
- mock `getBoundingClientRect` 让 Recharts 正常渲染（**必须含 left/top 字段**）
- E2E：Playwright 仅本地跑、不进 CI（首次需 `npx playwright install chromium`）

### 隐私红线（最高优先级）

> `private-fixtures/` 为用户真实骑行数据，已 gitignored。
> **严禁提交到 git，严禁在测试代码中引用。**
> 相对地，`author-data/` 是有意公开的作者数据源，可以提交。

## 6. Git 提交规范

### 6.1 前缀体系

| 前缀 | 含义 |
|---|---|
| `[NF]` | 新功能（New Feature） |
| `[BF]` | 缺陷修复（Bug Fix） |
| `[IM]` | 改进/重构（Improvement） |
| `[CU]` | 版本发布、文档状态回填等杂务更新 |

### 6.2 提交信息格式（经过一次明确化迭代，见提交 `7de1739`）

- Subject：一句话概括本次提交做了什么，简洁不堆砌细节，前缀后**无冒号**
- 正文：bullet list（`-` 开头）承载全部细节——新增/修改了哪些文件与函数、关键实现点、
  测试情况（如「全量 NNN/NNN + lint/build 绿」）、文档同步说明
- 版本号变更写进正文 bullet（如 `- 版本 2.12.0 → 2.13.0`），不追加在 Subject 尾部

```text
✅ 正例（参照 9d36a88，勿回退旧风格）：
[NF] 详情页报告化：一句话总结 + 核心指标精选 + 更多指标折叠

- 新增 src/features/activity/rideSummary.ts …
- 新增 RideSummaryBanner 组件挂详情页顶部 …
- 测试 14 新增，全量 830/830 + lint/build 绿
- 版本 2.9.0 → 2.10.0

❌ 反例（已废弃）：
[NF]: 详情页新增A+B+C+D+E…版本 2.10.0   ← 把全部功能点用「+」串进一行长 Subject
```

> 经验：这套格式是被早期的「单行超长 Subject」逼出来的。规范本身也要迭代——
> 出现反例后在 CLAUDE.md 里同时写下正例与反例，后续 Agent 才不会回退。

### 6.3 其他硬性规定

- **无 AI 署名**（不加 Co-Authored-By 等）
- 提交身份固定 `999bug <999bug@users.noreply.github.com>`（项目级 git config 已设，勿改）
- **每个功能/任务单独一个 commit**（便于回滚与 PROGRESS.md 对账）
- Hooks 自动化：
  - `package.json` 的 `prepare` 脚本设置 `core.hooksPath .githooks`（npm install 即自动生效）
  - `.githooks/post-commit`：存在 `.codegraph/` 时自动执行 `codegraph sync` 同步索引

## 7. 版本与发布流程

1. **版本策略**：每次 push 一组功能提交前，`package.json` 升一次 minor 版本；
   `__APP_VERSION__` 由 vite define 自动读取，侧边栏底部显示且可点击跳转 `/changelog`
2. **更新日志页**：`src/features/changelog/changelogData.ts` 倒序维护，
   每版发布时在头部追加条目
3. **CI 流水线**（push main 触发）：lint → test → 构建作者数据快照 → build → 部署 Pages
4. 快照任一 FIT 解析失败 CI 即失败（fail-fast，防坏数据上线）
5. 构建产物 `public/author-data/`、`dist/` 均 gitignored，由 CI 重建

## 8. Agent 协作工作流（跨会话 / 跨工具）

这是本项目最有价值的经验沉淀，解决的核心问题是：**上下文会断，进度不能断**。

### 8.1 §0 进行中任务登记制（中断恢复机制）

`docs/PROGRESS.md` §0 是一张活的任务表：

- **每开始一个新任务先登记**（状态 🔄 运行中 + 注明负责 agent）
- 每完成一步更新状态列；全部完成并提交后移出或标 ✅
- 表格记录：任务背景（用户反馈原话）、拆解后的子任务 T1~Tn、当前进度、下一步动作
- 会话因上下文满 / 费用不足 / 手动停止而中断时，下一个 agent 读 §0 即可无损接续，
  **避免重复工作或遗漏**

### 8.2 任务队列模式（§6 UI 改造案例）

大方向改造（如「UI/体验专项」）采用队列推进：

- 外部评审报告 + 线上截图实测（`scripts/capture-screenshots.mjs` 自动截 8 页）**交叉核实**，
  逐项标注「已完成勿重做 / 半成品 / 真问题」，避免重复劳动
- 任务按「用户感知价值 ÷ 改造成本」排优先级（P0 → P1）
- 每个 P0 任务单独 commit；完成后回填状态 ✅ 并附 commit 号
- 截图实测发现的额外问题单独记录（§6.3），并入相近任务处理

### 8.3 Spec → Plan → Task 工作流（superpowers 模式）

大功能（如「作者数据快照 + 双数据源」）三步走：

1. **设计文档**（specs/）：背景目标、非目标、总体架构、方案对比与用户确认结论
2. **实现计划**（plans/）：按依赖关系拆 Task，每个 Task 列出 Modify/Create 文件、
   Produces/Consumes 接口签名、checkbox 步骤、甚至直接给出代码骨架
3. **Global Constraints 置顶**：把全局规范（注释语言、提交格式、undefined≠0、
   只读边界、每 Task 结束全绿才提交）复制进计划文件头部，执行 agent 无需跳读

### 8.4 多工具协作约定

- `CLAUDE.md` 服务 Claude Code；`AGENTS.md` 服务 Codex / pi / opencode 等其余工具；
  两份文件内容语义一致，改规范时同步更新
- 所有工具共享同一份 `docs/PROGRESS.md` 作为唯一事实来源
- 方案分歧（如作者数据怎么发布）先给用户对比选项，**用户确认后再写入 spec**（「状态：已批准」）

### 8.5 完成定义（Definition of Done）

每个任务收尾必做：

```
npm run lint && npm run test && npm run build   # 三绿
→ 更新 docs/PROGRESS.md（§0 状态 + 文件清单）
→ 升 minor 版本 + 追加 changelog
→ 单独 commit（规范格式）
→ push 后确认 CI 绿
```

涉及主链路的改动补 E2E。

## 9. 全局 Agent 配置层（`C:\Users\SERVER`）

多工具协作不止发生在项目内——全局配置本身也是一套沉淀下来的体系。
原则：**全局放跨项目通用规则，项目规范下沉到各仓库**，两层互不重复。

### 9.1 全局指令文件与 CodeGraph 约定

- `~/.claude/CLAUDE.md` 与 `~/.codex/AGENTS.md` 内容完全一致（CodeGraph 自动注入维护，
  `<!-- CODEGRAPH_START/END -->` 标记区块），保证 Claude Code 与 Codex 行为对齐
- CodeGraph 使用约定（结构性问题优先走索引，别用 grep 重复劳动）：
  - 定义/调用方/被调/影响面 → `codegraph_search / callers / callees / impact`
  - 跨函数链路追踪 → `codegraph_trace`（一次返回全路径，含 React/回调动态跳转）
  - 取上下文 → `codegraph_context`（一次顶 search+node 两连）；多符号源码 → `codegraph_explore`
  - **信任索引结果，不要再用 grep 复核**（AST 解析比 grep 更准更快）
  - 文件刚改完别立刻查（watcher 有 ~500ms 防抖延迟）
  - 项目未建索引时主动询问用户是否 `codegraph init -i`

### 9.2 Claude Code 全局设置要点（`.claude/settings.json`）

- **分档模型映射控成本**：经中转 API 接入多家模型——haiku 档→GLM、

- `CLAUDE_CODE_EFFORT_LEVEL=max`：推理力度拉满
- **Windows 通知 hook**：Notification（需要人工操作）与 Stop（任务完成）事件触发
  BurntToast 弹窗——长任务不用盯屏
- 自定义 statusLine（pwsh 脚本实时显示状态）
- **插件矩阵**：superpowers（spec→plan 工作流）、code-review、code-simplifier、
  context7（库文档）、frontend-design、playwright、security-guidance 等
- `systemPrompt` 固定「始终使用简体中文交互」；shell 固定 pwsh 并配置 GIT_BASH_PATH

### 9.3 自定义 Skill：fix-report（四段式修复汇报）

`~/.claude/skills/fix-report/SKILL.md` 是典型的个人经验资产化——bug 修完后说一句
「生成修复说明」，Agent 按固定模板汇报：

```
### 问题来源   场景/环境 + 关键报错
### 问题原因   根因一句话讲透（引入改动、触发条件、为何之前没暴露）
### 问题解决   改了什么 + 验证结果（编译/测试通过情况）
```

## 10. 踩坑清单（血泪经验）

### FIT 解析

- **Stream 校验顺序**：`isFitFile` / `checkFitIntegrity` 必须在 `read()` **之前**调用——
  read 消费 stream 之后会误报 false
- FIT 解析放 Web Worker（jsdom 测试环境自动降级主线程）；失败文件进台账、可重试

### GPX / 导入

- 带命名空间前缀的扩展标签（如 `TrackPointExtension` 下的 hr/cad/power）用
  `getElementsByTagName` 查不到，必须 `getElementsByTagNameNS` 按局部名匹配
- **FileList 是 live 引用**：`event.target.value = ''` 重置输入会清空已保存的 FileList，
  导致选文件后页面无反应——先 `Array.from()` 转数组再重置
- Strava 批量导出的标题还原靠 CSV「文件名」列（数字 ID）匹配；手动下载的文件名即标题
  但纯数字要跳过；描述/估算功率仅 CSV 有对应行时生效
- 批次内混合 FIT/GPX 时按扩展名分发解析器，GPX 用动态 import 独立分包不进首屏

### 存储（Dexie）

- **非索引字段增删不需要升 DB_VERSION**（如 `FileEntity.data`）；改索引列才需要升版本
- 导入摘要需含 `normalizedPower`，否则训练状态聚合缺数据

### 图表（Recharts）

- recharts 3 升级坑：`activeTooltipIndex` 变成字符串，`typeof number` 判断失效，
  图表悬停不再上报时间戳 → 封装 `activeTooltipIndexToNumber` 归一化共用
- jsdom 下组件渲染图表必须 mock `getBoundingClientRect` 且含 `left/top`

### 地图

- 高德底图为 GCJ-02（火星坐标）：降级到高德瓦片后展示坐标统一做 WGS-84 → GCJ-02 转换
  （境外坐标原样返回）
- 瓦片源自动降级策略：连续 3 张失败且期间无成功 → OSM 降高德，sessionStorage 记忆
- 大量迷你地图实例会拖垮页面：懒加载（IntersectionObserver rootMargin）+ fitBounds 禁交互

### 性能

- 赛段路径校验 O(N×M) 主线程暴力计算会导致导入后页面卡死；
  解法组合拳：包围盒预筛 + 轨迹抽稀 ≤200 点 + 中位数距离提前退出 + 以穿越段为 key
  缓存校验结果 + Web Worker 化（jsdom 无 Worker 同步回退）
- 图表大数据量：downsample 封顶（剖面 ≤800 点、曲线 ≤1000 点）+ 子树 memo +
  悬停期间抑制自渲染

### 环境

- bash 宿主进程注入 runner 上下文会导致 vitest 全量 0 用例执行——换 PowerShell 通道跑，
  与代码无关（排查测试异常时先排除宿主环境因素）
- README 截图脚本需要 HTTPS_PROXY 支持，瓦片页等待策略避开 networkidle 超时

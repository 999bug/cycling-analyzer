# 架构总览

> 个人骑行数据分析网站（Strava Lite）的整体架构说明。产品规格出处见《个人骑行数据分析网站——Agent 开发规格说明》，功能状态清单见 `PROGRESS.md`，开发约定见根目录 `CLAUDE.md` / `AGENTS.md`。
>
> 更新日期：2026-09-11（对应版本 2.61.x）

## 1. 一句话概括

纯前端单页应用：FIT 文件**在浏览器内**解析，数据存 **IndexedDB**，部署在 **GitHub Pages**；默认展示作者公开数据快照（只读），访客也可导入自己的数据（本地可写）——**双数据源**。

## 2. 技术栈

| 类别 | 选型 |
| --- | --- |
| 框架 | React 19 + TypeScript（strict） |
| 构建 | Vite 8（`tsc -b` 类型检查 + vite build），vite-plugin-pwa |
| 路由 | react-router-dom 7（生产 basename `/cycling-analyzer`） |
| 状态 | zustand 5（`src/stores/*`） |
| 持久化 | Dexie 4（IndexedDB 封装，库名 `cycling-data`） |
| FIT 解析 | @garmin/fitsdk（仅在 `src/fit/decoder` 内出现） |
| 图表 | Recharts 3 |
| 地图 | Leaflet + react-leaflet（OSM / 高德瓦片自动降级） |
| 压缩 | fflate（zip/gzip，导入扫描与快照构建共用） |
| 测试 | Vitest + jsdom + fake-indexeddb + Testing Library；Playwright（e2e，本地跑） |

## 3. 分层架构（硬边界）

```mermaid
flowchart TD
    subgraph 展示层
        P[pages/* 14 个路由页面]
        C[charts/* Recharts 图表]
        M[map/* Leaflet 地图]
        K[components/* 通用组件]
    end
    subgraph 状态与数据接入
        S[stores/* zustand<br/>dataSource / import / ui / activityFilter]
        H[useActivityRepository()<br/>组件统一仓库入口]
        T[types/activity.ts<br/>领域模型 = 唯一跨层契约]
    end
    subgraph 业务功能域
        F[features/*<br/>import · activity · dashboard · statistics<br/>calendar · segments · heatmap · routes<br/>training · analysis · insights · yearReview<br/>records · settings · pwa]
    end
    subgraph 数据管线 src/fit
        D[fit/decoder<br/>封装 @garmin/fitsdk] --> N[fit/normalizer<br/>SDK 结构 → 领域模型] --> CA[fit/calculator<br/>统计指标计算]
    end
    subgraph 存储层 src/storage
        R[repositories/*<br/>activity · file · settings · segment]
        DB[(Dexie: cycling-data<br/>activities · activity_blobs<br/>files · settings)]
        AU[作者快照 只读<br/>public/author-data]
    end
    展示层 --> 状态与数据接入 --> 业务功能域 --> 数据管线 --> 存储层
    R <--> DB
    R -.-> AU
```

**硬约束（规格 §42）**：

- React 组件**禁止**直接调用 `@garmin/fitsdk`；UI 只依赖 `src/types/activity.ts` 领域模型与 repository 接口
- 单位固定：米 / m/s / bpm / rpm / W、Unix 秒、十进制度；**缺失字段 = undefined ≠ 0**，UI 显示 `—`
- 组件不自己 new 仓库，统一经 `useActivityRepository()` 取当前数据源的仓库；作者源只读，写操作 UI 按源隐藏

## 4. 目录结构

```
src/
├─ main.tsx            # 入口：路由 basename、主题/侧边栏/统计口径恢复、数据源探测、发版兜底刷新
├─ app/                # App 壳、router.tsx（ROUTES 常量）
├─ pages/              # 14 个页面：仪表盘 / 活动列表 / 活动详情 / 统计 / 日历 / 设置 /
│                      #   热力图 / 路线图 / 路段 / 年度回顾 / 训练计划 / 表现 / 更新日志 / 致谢
├─ features/           # 业务功能域（页面级逻辑 + 纯函数计算），见下表
├─ components/         # 跨页面通用组件（数据源切换、迁移横幅、错误边界等）
├─ charts/             # Recharts 封装（指标图、功率曲线、降采样、坐标轴）
├─ map/                # Leaflet 封装：瓦片源与降级、轨迹回放、路线配色、轨迹简化、本地瓦片缓存
├─ stores/             # zustand：数据源 / 导入 / UI / 活动筛选
├─ hooks/              # useActivityRepository、单位格式化、PWA 安装等
├─ types/              # activity.ts 领域模型（唯一跨层契约）、activityType.ts
├─ fit/                # 数据管线：decoder / normalizer / calculator / worker（Web Worker）
├─ storage/            # Dexie db.ts、repositories、作者快照客户端、瓦片缓存、扫描缓存、逐点迁移
└─ utils/              # 指纹、格式化、导航
```

`src/features/` 功能域一览：

| 域 | 职责 |
| --- | --- |
| `import` | 文件/zip/佳明导出包扫描展开、Worker 解析客户端、Strava CSV 标题还原、错误分类 |
| `activity` | 详情页各区块：分段/爬坡/成就/对比/训练效果/轨迹清洗 |
| `analysis` | 跨活动分析：强度、区间、功率曲线、FTP 估算、训练状态、表现趋势、质量分 |
| `statistics` / `dashboard` | 统计页与仪表盘的聚合卡片、趋势图 |
| `segments` | 路段匹配、排行榜（独立 Worker） |
| `heatmap` / `routes` | 热力图网格、路线聚类 |
| `calendar` / `records` / `insights` | 日历热力图、个人纪录、洞察 |
| `training` / `yearReview` | 训练计划、年度回顾与分享卡片 |
| `settings` | 主题、侧边栏、有效训练配置 `getEffectiveProfile(source)` |
| `pwa` | SW 更新检测、安装引导 |

## 5. 导入数据流

```mermaid
flowchart TD
    A[文件输入<br/>.fit / .fit.gz / zip / 佳明导出包] --> B[scanner 展开归档 fflate<br/>zip 递归×2 层 · gzip 解压]
    B --> C[Web Worker 解析<br/>decoder → normalizer → calculator]
    C -->|失败| Z[files 台账<br/>可重试]
    Z -.重试.-> C
    C --> E[内容指纹判重<br/>解压后内容哈希 · .fit 与 .fit.gz 等价]
    T[标题还原支线<br/>Strava CSV 文件名匹配<br/>佳明摘要 JSON ±2s 匹配] -.-> G
    E --> G[(写入 Dexie: cycling-data<br/>activities 摘要 + activity_blobs 逐点)]
```

要点：

- **解析在 Web Worker**（`src/fit/worker/`），jsdom 测试环境自动降级主线程
- **活动 ID = 文件内容指纹**（解压后哈希），同一活动 `.fit` 与 `.fit.gz` 判重一致，天然支持快照深链
- **Strava 标题还原**：批量导出 CSV 的「文件名」列匹配（跨行引号感知）；佳明 GDPR 导出包按摘要 JSON `startTimeGmt` 与 FIT 开始时间 ±2s 匹配
- 失败文件进 `files` 台账，UI 可重试

## 6. 存储模型（Dexie `cycling-data`）

| 表 | 内容 | 说明 |
| --- | --- | --- |
| `activities` | 活动摘要（含 `normalizedPower`） | 列表/聚合只查摘要；训练状态聚合依赖摘要中的估算功率 |
| `activity_blobs` | 逐点数据，**每活动一行**（v5） | IndexedDB 无批量删除 API，整活动一行使删除/导入毫秒级；`getRecords` 按需加载 |
| `activity_records` | 旧逐点行表（迁移兜底） | 后台迁移（`recordsMigration.ts`，幂等续传 + 心跳锁）完成后 v6 删除；读取新表优先、旧表兜底 |
| `files` | 文件台账 | 导入成功/失败记录，失败可重试 |
| `settings` | 用户设置、训练配置 | 训练配置随数据源切换（`getEffectiveProfile(source)`） |

另有无状态缓存：`tileCache`（离线地图瓦片）、`scanCache`（导入扫描结果）。

## 7. 双数据源

- `dataSourceStore` 管理两个源：**作者的数据**（CI 构建的静态快照 `public/author-data/`，只读，由 `npm run build:author-data` 全量重建，任一 FIT 解析失败 CI 即失败）与**我的数据**（本地 IndexedDB，可写）
- 组件统一经 `useActivityRepository()` 获取当前源的仓库（`authorData/authorActivityRepository.ts` 或本地 repository），训练配置随源切换
- 作者源下所有写操作 UI 一律隐藏；快照探测失败（如本地 dev 未生成）静默回退本地源

## 8. 地图与瓦片降级

- 默认 OSM 瓦片；**连续 3 张失败且期间无成功**自动降级高德瓦片，sessionStorage 记忆（key `cycling-map-tile-fallback`）
- 高德底图为 GCJ-02 坐标，降级后展示坐标统一做 WGS-84 → GCJ-02 转换（境外原样返回）；详情页与热力图页共用 `FallbackTileLayer`
- 轨迹渲染支持简化（`simplify.ts`）、按指标配色、轨迹回放（`replayEngine` / `replayCore`）

## 9. 路由与部署

- SPA 路由 14 条（`src/app/router.tsx` 的 `ROUTES`）；生产 basename `/cycling-analyzer`，dev `/`
- GitHub Pages 部署：`public/404.html` 处理深链接；CI 重建 `public/author-data/` 与 `dist/`
- PWA（vite-plugin-pwa）：SW 更新策略为导航网络优先 + 静默激活；`vite:preloadError` 触发一次自动刷新兜底旧版本懒加载 chunk 404

## 10. 测试架构

- Vitest + jsdom，`tests/setup.ts` 全局注册 fake-indexeddb；DB 测试用真 Dexie 实例注入
- FIT 样例在 `tests/fixtures/`（Garmin 官方公开样例 + 合成 GPS 文件）；**`private-fixtures/` 用户真实数据 gitignored，严禁提交或引用进测试**
- 页面测试用 MemoryRouter；数据加载支持注入；mock `getBoundingClientRect` 让 Recharts 可渲染
- e2e 用 Playwright（本地跑，不进 CI）

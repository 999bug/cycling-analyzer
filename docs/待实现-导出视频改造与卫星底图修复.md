## 二、任务二：卫星底图在作者数据区域退化成矢量图

### 2.1 现象与复现

任一作者快照活动 → 地图右上角切「卫星」或「卫星+路网」→ **切换前视口覆盖的那片区域仍显示路网图**，其余区域是真卫星；等待 12 秒不消退（非加载时序问题）。

### 2.2 根因（已定位并验证）

- `src/map/localTiles.ts`
  - `parseAmapTileUrl(url)` 只从 URL 抠 `x/y/z`，**不区分矢量(webrd style=8) / 卫星(webst style=6)**
  - `hasLocalTile(z,x,y)` 查的 `tiles-manifest.json` key 也只有 `"z/x/y"`，**同样没有底图模式**
- `src/map/CachingTileLayer.tsx` 的 `loadTile()`「本地预缓存优先」分支因此对卫星请求也返回本地矢量瓦片：

```ts
// 预缓存静态瓦片优先（作者数据区域）：同域直读零跨域，命中则完全绕过在线请求
const amapCoords = parseAmapTileUrl(url)
if (amapCoords !== null && (await hasLocalTile(amapCoords.z, amapCoords.x, amapCoords.y))) {
  tile.src = localTileUrl(amapCoords.z, amapCoords.x, amapCoords.y)
  return
}
```

**影响范围**：凡作者快照覆盖区域（`public/author-data/tiles/`），访客切卫星都会看到矢量/卫星混杂；用户导入自有数据（其他地区）不触发。**内测朋友点过卫星的话已经看到过这个 bug。**

### 2.3 修复方案（推荐）

**非 normal 模式直接跳过本地预缓存**——本地本就只预缓存了矢量瓦片，没必要让卫星去查它：

1. `src/map/CachingTileLayer.tsx`：新增 prop（如 `allowLocalTile?: boolean`，默认 `true`），`loadTile()` 中该分支加前置判断
2. `src/map/FallbackTileLayer.tsx` L80 渲染 `CachingTileLayerComponent` 时传入 `allowLocalTile={mapMode === 'normal'}`

> 备选方案：manifest key 加模式前缀（`normal:z/x/y` / `satellite:z/x/y`），需同时预缓存两套瓦片、体积翻倍，**不推荐**。

### 2.4 测试要点

- 单测：非 normal 模式下 `loadTile` **不调用** `hasLocalTile` / `localTileUrl`
- 回归：`mapMode === 'normal'` 时本地预缓存仍生效（离线可用特性不能被破坏）
- 手工：作者数据区域切卫星，确认整屏均为卫星影像；`localTiles` 已有 `resetManifestForTest()` 测试辅助可用

## 二·补、全屏后地图不重新适配视野（2026-09-10 追加发现）

> 这条是录制视频时"画面太小"的根因，**优先级建议排在卫星 bug 之前**——所有访客都会遇到。

### 现象

活动详情页地图**全屏后，轨迹缩成画面中间一小团**。实测（1080×1920 全屏容器、210km 轨迹）：

| | 横向占画面 | 纵向占画面 |
|---|---|---|
| 实测 | **44.0%** | **10.2%** |
| fitBounds 应有 | ≈96% | ≈22% |

差了 **2.15 倍**。而 `fitBounds` 的规则本就是让轨迹充满容器，说明全屏后**根本没重新适配**。

### 根因

`src/map/ActivityMap.tsx` 的 `FitBounds` 组件（L122-132）：

```tsx
useEffect(() => {
  if (points.length >= MIN_POINTS) {
    const latLngs = points.map((point) => [point.latitude, point.longitude] as [number, number])
    map.fitBounds(latLngs, { padding: [24, 24] })
  }
}, [map, points])   // ← 只依赖轨迹点
```

全屏时地图容器从 `812×340` 变成 `1080×1920`，Leaflet 的 `invalidateSize()`（由 `FullscreenSync` 触发）
**只保持 center + zoom，不会重新 fitBounds**。于是地图沿用了"宽扁容器"算出来的缩放级别，
在竖屏大容器里轨迹就显得极小。

### 修复建议

利用 Leaflet 在 `invalidateSize()` 时触发的 `resize` 事件重算：

```tsx
useEffect(() => {
  if (points.length >= MIN_POINTS) {
    const latLngs = points.map((point) => [point.latitude, point.longitude] as [number, number])
    const fit = () => map.fitBounds(latLngs, { padding: [24, 24] })
    fit()
    map.on('resize', fit)
    return () => {
      map.off('resize', fit)
    }
  }
  return undefined
}, [map, points])
```

### ⚠️ 实现时必须注意

- **不要覆盖用户的手动操作**：如果用户已经手动缩放/拖拽过地图（组件内可能有 `userZoomedRef` 之类的标记），
  尺寸变化时不应强行 fit 回全景，否则会打断用户。
- **区分全屏进出与窗口缩放**：两者都会触发 `resize`，行为应一致（都重新适配）才符合直觉。
- 若担心 `resize` 触发过频，可加防抖（如 120ms）。

### 测试要点

- 全屏前后各截一帧，轨迹像素包围盒宽度应接近容器宽度（≥90%）
- 退出全屏后视野同样正确，不残留放大状态
- 用户手动缩放后，尺寸变化不应把视野强行拉回（若采用上面的"尊重用户操作"策略）
